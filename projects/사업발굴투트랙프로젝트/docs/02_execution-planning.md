# 실현계획 수립 — 세부 목적과 방법

`00_project-overview.md`의 공통 원칙, `01_business-idea-discovery.md`의 기회 카드를 전제로 한다.

## 목적

"찾은 기회를 어떻게 실행할 것인가"를 구체적 계획으로 만든다. 입력값(기회 카드)이 트랙 A(지속가능)냐 트랙 B(순간)냐에 따라 완전히 다른 형태의 계획이 나온다.

---

## 트랙 A 대응: 지속가능 실행 로드맵

### 구성 요소
1. **MVP 정의** — 페인포인트 검증에 쓰인 원문 인용을 기반으로, 최소 기능으로 뭘 만들면 그 불편함이 해소되는지 정의
2. **90일 마일스톤** — 리서치→프로토타입→소규모 테스트→피드백 반영 순으로 분기
3. **소싱/제작 계획** — 제품이면 소싱 채널·리드타임·초기 발주 수량, 서비스면 개발 리소스·기술 스택
4. **초기 마케팅 채널** — 발굴 단계에서 확인된 릴스/커뮤니티를 그대로 첫 유통 채널로 재사용 (신규 채널 개척 비용 절감)
5. **손익분기 계산** — 초기 투자 대비 최소 판매/구독 수 역산

### 산출물: 실행 로드맵
```
- 기회명: (기회 카드 연동)
- MVP 정의:
- 90일 마일스톤: [1개월차 / 2개월차 / 3개월차]
- 소싱/제작 계획:
- 첫 마케팅 채널: (발굴 단계 릴스/커뮤니티 재사용)
- 손익분기 계산:
- 리스크와 중단 기준(Stop 조건):
```

### AI 에이전트 배치 아이디어 (1인 기업가용)
지속가능 트랙은 속도보다 정확도가 중요하므로, 아래 역할을 개별 에이전트로 분리해서 운영 가능:
- 소싱 리서치 에이전트 (공급처 비교, 견적 수집)
- 카피라이팅/콘텐츠 에이전트 (발굴 단계 후킹 패턴 재사용)
- 재무 시뮬레이션 에이전트 (손익분기, 시나리오 분석)
- CRM/고객 응대 에이전트 (초기 문의 대응)

## 트랙 B 대응: 속도 플레이북 (말랑이류)

### 구성 요소
1. **Go/No-Go 데드라인** — 속도 기회 카드의 "데드라인"을 넘기면 자동으로 Stop 처리
2. **소싱 실행** — 1688/알리 발주부터 국내 입고까지 리드타임 역산, 최소 발주 수량으로 리스크 제한
3. **크리에이터 시딩 계획** — 어떤 유형의 크리에이터(팔로워 규모/카테고리)에게 얼마나 빨리 제품을 보낼지
4. **재고 회전 계획** — Peak 진입 예상 시점 전에 1차 재고를 소진할 수 있는지 역산
5. **철수 기준** — Declining 신호(조회수 하락, 광고주 수 급증 후 정체) 감지 시 즉시 추가 발주 중단

### 산출물: 속도 실행 플레이북
```
- 상품/트렌드명: (속도 기회 카드 연동)
- Go/No-Go 데드라인:
- 소싱 실행 계획: (발주처, 리드타임, 최소 수량)
- 크리에이터 시딩 계획: (대상 규모, 발송 수량, 목표 기간)
- 재고 회전 목표: (1차 재고 소진 목표일)
- 철수 신호: (이 조건이 뜨면 즉시 중단)
```

### 자동화 우선순위
트랙 B는 계획 자체보다 **실행 속도**가 핵심이므로, 실현계획 단계에서도 아래는 반드시 자동화 대상으로 분리한다:
- 소싱처 견적 자동 수집/비교
- 크리에이터 컨택 메시지 초안 자동 생성 (일괄 발송용)
- 재고/판매 추이 일일 모니터링 알림

## 두 트랙 공통: 사후 검토

실행 후에는 트랙 무관하게 아래를 기록해서 다음 발굴 단계(`01_business-idea-discovery.md`)의 판단 기준을 보정하는 데 쓴다.
- 예측했던 스코어(시장 갭 스코어 / 모멘텀 스코어)와 실제 성과의 괴리
- 놓쳤던 신호가 있었다면 무엇이었는지 (예: 말랑이 사례처럼 "그때 왜 못 봤는가")
