## 2. 수익을 못 내는 이유 (영향 큰 순)

### ① 비용이 엣지를 다 먹는다 — 가장 큰 원인
딥코인 USDT 무기한 taker 수수료는 0.06%다. 시장가로 진입하고 SL/TP가 트리거돼 시장가로 청산되므로
왕복 0.12%이고, 슬리피지를 더하면 약 0.16%다. 현재 SL은 가격 기준 0.3~0.5%다. 그래서 **매 거래 비용이
리스크(1R)의 30~50%**다. 엣지가 +0.06R인 전략이 비용 0.4R을 내면 남는 게 없다.

결함을 하나씩 고치며 측정한 결과(BTC 최근 180일, `backtest/ablation_v2.py`):

| 단계 | OTE 단독 거래당 R | OTE 단독 수익률 | 4전략 체인 수익률 |
|---|---|---|---|
| 0 옛 엔진 재현 | +0.25 | +2.7% | +3.0% |
| 1 라이브와 같은 캔들 개수 (D1 레짐 작동) | +0.09 | -20.0% | +19.2% |
| 2 미래 데이터 누수 제거 | +0.07 | -25.9% | -37.2% |
| **3 수수료·슬리피지 반영** | **-0.34** | **-56.7%** | **-79.4%** |
| 5 라이브 일한도·쿨다운까지 (= 정직한 라이브) | -0.34 | -56.3% | -77.0% |

### ② 비용을 빼도 신호에 방향성 엣지가 없다
정직한 데이터에서 OTE의 비용 전 기대값은 +0.06R이다. 승률은 약 27%인데, RR 2.5의 손익분기 승률이 28.6%다.
워뇨띠 분석(진입 트리거만으로는 51~52%)에서 나온 결론이 15분봉 ICT에서도 그대로 재현된다.

### ③ 백테스트 엔진 결함 때문에 잘못된 확신을 가졌다
- **D1 레짐 필터가 백테스트에서 한 번도 작동하지 않았다.** `engine.py`는 D1을 50개로 잘랐는데
  `get_market_regime()`은 55개 미만이면 무조건 `ranging`을 돌려준다. P3 원칙(D1 역방향 금지)은 라이브에서만 작동했다.
- **미래 데이터 누수:** HTF 캔들을 "시작시각 ≤ 현재"로 잘라서, 아직 안 끝난 1H/1D 캔들의 최종 종가를 썼다.
- **수수료 0, 신호 캔들 종가에 즉시 체결.**
- **검증 기간이 6개월 한 구간뿐이었다.** 한 국면에 과적합되기 쉽다.

### ④ 라이브와 백테스트의 판단 시점이 다르다
라이브 루프는 수십 초마다 **진행 중인(미완성) 15분봉**으로 판단한다. 15분봉 확인캔들(`_m15_confirms`)조차
아직 안 끝난 봉의 방향을 본다. 백테스트는 완성된 종가로만 판단한다. 이 차이는 5분 단위 시뮬레이션으로
측정했다(→ 6절).

### ⑤ 거래당 리스크 10%는 파산 구조다
승률이 27%면 100거래 안에 8연패가 나는 게 정상 범위다. 10% 리스크로 8연패하면 계좌의 -57%다.
09-30 하루 4연패에 -38%가 실제로 나왔다.

### ⑥ 기타 발견
- `tuning.json`의 `active_symbols`에 **XRP가 들어 있다.** HANDOVER/CLAUDE.md는 "XRP 비활성"이라고 적혀 있어 문서와 다르다. 의도인지 확인이 필요하다.
- `ict_engine.get_ote()` / `find_breaker_blocks()`가 가격을 `round(..., 2)`로 반올림한다. 가격이 1.5 수준인 XRP에서는 OTE 구간이 1센트 단위로 뭉개진다.
- 현재 체인(OTE+MTF, m15_confirm 2)은 BTC 기준 **6개월에 2~3건**만 거래한다. 사실상 쉬고 있는데, 그 2건도 손실이었다.

설계해서 이 불일치를 구조적으로 없앴다.

1. **지금 실거래 체인을 멈추거나 리스크를 10%에서 1%로 낮추기.** 정직한 백테스트상 현재 체인은 거래당 -0.3~-0.6R이다.
2. `RegimeTrend`(롱, BTC)를 `server.py`에 이식하고 **sim 모드로 4주 전진 테스트**한다. 1H/4H/D1 마감 시점에만 판단하므로 루프가 단순해진다.
3. 전진 테스트 결과가 백테스트 범위(4주 0~3건, 거래당 R>0) 안에 들면 real, 리스크 1%로 시작한다.
4. 앞으로 백테스트는 `engine_v2`로만 한다. `engine.py` 숫자는 신뢰하지 않는다.

## 재현 명령어

```bash
python backtest/run_v2.py --sym BTC-USDT-SWAP --strat legacy,legacy_all4            # 현재 전략 (2년, 정직)
python backtest/ablation_v2.py --sym BTC-USDT-SWAP --days 180 --chain OTE --m15 0  # 결함별 영향
python backtest/run_v2.py --sym BTC-USDT-SWAP --strat regime_trend_long --horizon 4y
python backtest/robust_v2.py --strat d1t                                            # 견고성 그리드
python backtest/edgecase_v2.py --sym BTC-USDT-SWAP --strat regime_trend_long        # 엣지케이스
```
