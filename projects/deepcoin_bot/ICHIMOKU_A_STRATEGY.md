# 일목균형표 A 기준 구름 상태 전략

이 문서는 `ichimoku_cloud_state.py`의 규칙과 호출 방법을 설명한다. 이 모듈은 **모든 스왑 심볼에 각각 적용**할 수 있도록 심볼을 인자로 받고, 특정 코인 목록을 코드에 고정하지 않는다.

## 규칙

- 시간축: 일봉, 기본 일목균형표 설정(전환선 9, 기준선 26, 선행스팬 B 52, 표시 이동 26)
- 구름 기준: 차트의 **현재 표시 구름**. 즉 오늘 캔들 위치에 표시되는 선행스팬 값을 사용하며, 오늘 기준 26개 일봉 전에 계산된 선행스팬 A/B다.
- 신호는 완결된 일봉 종가로만 갱신한다. 진행 중인 일봉은 제외한다.
- 종가가 구름 상단보다 높으면 목표 상태는 롱, 구름 하단보다 낮으면 숏, 구름 안(경계 포함)이면 무포지션이다.
- 현재 포지션과 목표 상태를 비교해 `ENTER`, `EXIT`, `HOLD`, `REVERSE`, `FLAT` 행동을 반환한다. `REVERSE`는 기존 포지션을 닫은 뒤 반대 방향으로 전환하라는 뜻이다.
- 4% 장대봉 필터는 A 기준에 포함하지 않는다. A는 구름 기준 상태 전환 전략이다.

## 호출

```python
from ichimoku_cloud_state import evaluate

# d1 candles are the per-symbol result of server._klines(sym=symbol, bar="1D", n=120)
decision = evaluate(d1_candles, symbol="ETH-USDT-SWAP", position=None)
```

예를 들어 `decision["action"] == "ENTER"`이고 `decision["signal"] == "LONG"`이면 롱 목표 상태다. 호출자는 같은 판단 결과가 반복 실행되는 동안 중복 주문을 내지 않도록 `candle_time`을 마지막 처리 일봉으로 기록해야 한다.

## 기존 봇에 연결할 때

현재 `_SIGNAL_CHAIN`은 15분봉 신호와 고정 SL/TP 검증을 쓰고, 포지션이 열린 동안에는 신규 진입 신호를 평가하지 않는다. 따라서 이 전략은 기존 체인에 단순히 추가하면 정의한 구름 청산이 수행되지 않는다. 연결 시에는 심볼별 완결 일봉이 새로 생겼을 때 `evaluate()`를 실행하고, `EXIT`/`REVERSE` 결과를 기존 포지션 청산 주문 경로에 연결해야 한다. 기존 체인에 등록하거나 실거래를 켜는 작업은 이 문서/모듈에 포함하지 않았다.

이 모듈은 규칙 계산부만 제공한다. 거래소 주문, 레버리지·사이징, 손절·익절, 수수료를 포함한 성과 검증은 별도 작업이다.
