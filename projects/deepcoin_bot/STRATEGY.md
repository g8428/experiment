## 4. 멀티전략 + SMC 기반 진입 원칙

### 4-1. 전략 우선순위 체인 (`ict_engine.py` `_SIGNAL_CHAIN`, `server.py` `_multi_strategy_signal`)

`backtest/strategy.py`로 6개월 BTC 백테스트한 4개 전략을 성과순으로 라이브에 이식. 심볼당 포지션 슬롯은 1개라 **순차 우선순위**로 처리 — 위에서부터 시도해 가장 먼저 시그널을 내는 전략을 채택.

| 순위 | 전략 | 핵심 조건 | 2026-09-23 6개월 BTC 백테스트 |
|---|---|---|---|
| 1 | **OTE** | 유동성 스윕 후 0.618~0.786 되돌림 재진입. 킬존 조건 없음(전역 P2가 대신 게이트) | +164.75% (82건, 승률29.3%) |
| 2 | **MTF** | OB/FVG 시그널 + 컨플루언스 점수 3점 이상 + 5m 확인봉 | +20.60% (20건, 승률30.0%) |
| 3 | **킬존NY전용** | OB/FVG 시그널을 뉴욕 세션으로만 한정 | +25.16% (65건, 승률20.0%) |
| 4 | **Breaker** | 실패 OB → 반대 POI 전환 지점 반응 | **-26.53%** (56건, 승률12.5%) — 최후순위, 승률 계속 낮으면 제외 검토 |

**단일 원본**: 4개 전략의 진입 조건(킬존·D1 레짐·1H 추세·구조·RR)은 전부 `ict_engine.py`의 `get_ote_signal / get_mtf_signal / get_killzone_signal / get_breaker_signal` 안에 있고, `backtest/strategy.py`는 그 함수를 감싸기만 한다. 그래서 백테스트 숫자는 실거래 코드 그대로의 결과다. 전부 `get_smc_signal`과 같은 dict 형태로 반환해 기존 파이프라인(패턴키/사이징)을 그대로 탄다. `pattern_key`에 전략명이 접두사로 붙어(`OTE+...`, `MTF+...`) 자가진화 통계가 전략별로 따로 쌓인다.

### 4-2. 라이브 진입 순서 (`server.py` `_run_claude_bot`) — 리스크 게이트만 얹는다
1. **일 한도** (`_can_trade`) — 초과 시 전부 스킵
2. **멀티전략 체인** (4-1) — 4개 전부 평가, 우선순위 순 첫 시그널 채택. 없으면 스킵
3. **직전 손절 구조 재진입 차단** — 직전 SL 레벨 ±0.2% 이내면 스킵
4. **쿨다운** — 청산 후 900초
5. **TP 최소(증거금 기준) / RR ≥ 2.5 / SL ≤ 2% / TP ≤ 15%** 검증 후 주문

라이브에는 전략 밖 시그널 필터(전역 킬존·RSI·EMA·BB·5m)가 **없다**. 2026-09-24까지 있었고, 그게 백테스트와 라이브를 다르게 만들던 원인이라 제거했다. 다시 넣고 싶으면 전략 함수 안에 넣고 백테스트를 다시 돌릴 것.

### SL/TP 설정
- **SL**: ICT 엔진 구조 레벨(OB 반대편) 우선, 없으면 ATR×0.8. 최소 `max(ATR×0.8, 0.3%)`, 최대 `sl_cap_pct` 2%
- **TP**: ICT tp1 (tp2가 2% 이내에 있으면 tp2). 없으면 ATR×2. 최대 `tp_max_pct` 15%
- **TP 최소**: 증거금 기준 `tp_min_margin_by_sym` (BTC 5% / ETH·XRP 3%) → 가격 기준으로는 ÷레버리지 (BTC 0.25%). 전역 `tp_min_margin_pct`는 0
- **주문가 정밀도**: 심볼별 `_PX_DEC` (BTC 1 / ETH 2 / XRP 4 자리)
- 딥코인 UI의 TP/SL %는 증거금 기준 → 가격 기준 × 20

## 6. 자가진화 규칙 — 두 층위로 나뉜다

### 6-1. 자동/Opus (가중치·원칙 미세조정 — 코드 변경 없음)
`pattern_key`는 `{전략명}+{킬존}+{BOS}+{POI}+...+{심볼}` 형태라 전략별·심볼별로 통계가 따로 쌓인다(2026-09-26부터 심볼 포함 — 이전엔 BTC/ETH/XRP가 구조만 같으면 섞였음). 이 층위는 `trade-supervisor`(Opus)와 `evolution/review_trades.py`가 담당하고, **`_SIGNAL_CHAIN` 구조(4-1)는 건드리지 않는다.** 가중치 파일(`backtest/pattern_weights.json`)은 실거래 전용이고 백테스트(`backtest_pattern_weights.json`)와 분리돼 있다 — 절대 합치지 말 것.

- 패턴 키당 **≥5 거래** 누적 시 통계 유의미
- 승률 ≥ 70% → 가중치 증가 / 허용 조건으로 추가
- 승률 ≤ 30% (5+거래) → 제한 조건으로 추가
- 승률 ≤ 20% (3+거래) → 즉시 금지 조건 고려
- 특정 전략(OTE/MTF/킬존NY/Breaker) 전체가 계속 저승률이면 "제외 검토" **제안**만 하고, 실제 체인에서 빼는 건 6-2로 넘긴다

절차:
1. `python evolution/review_trades.py` 실행
2. `pattern_stats.json` 의 `pending_updates` 확인 (전략별로 분리되어 보임)
3. 조건 충족 패턴 → `STRATEGY.md` 섹션 2 업데이트
4. 버전 올리기 (v1.x → v1.x+1), `## 진화 이력`에 기록, git 커밋

### 6-2. 수동/재영 (전략 자체 추가·제거 — 코드 변경 필요)
새 전략을 조사해서 추가하거나, 계속 구린 전략(현재 Breaker가 후보)을 빼는 건 사람이 판단한다. 방법은 `HANDOVER.md`의 "새 전략 추가/제거하는 법" 참고. 체인에 변화가 생기면 이 문서 섹션 4-1 표와 진화 이력을 반드시 갱신할 것.

## 7. 리스크 관리

- **레버리지**: 20x (`leverage`)
- **리스크**: 잔고의 10% / 트레이드 (동적 사이징, `risk_pct`)
  - 공식: `증거금% = min(80%, 10% / (SL거리 × 20))` × 패턴 가중치
  - 자본 기준 일별 PnL은 이 실제 증거금 비율로 계산 (`_rec(size_pct=...)`)
- **일 한도 (계좌 전체, 3심볼 합산)**: 거래 7회 / 손실 -25% / 손절 3회 / 수익 +10%
- **쿨다운**: 900초 (15분) / 트레이드 (`cooldown`)
- **거래 심볼**: `active_symbols` (현재 BTC, ETH). XRP는 ict_mtf 신호가 6개월 2건이라 비활성. 포지션 없을 때 tuning.json에서 빼면 해당 스레드 자동 정지
